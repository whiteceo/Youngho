# AI 업무 플랫폼 사업 타당성 검토

작성일: 2026-10-23

---

## 1. 개요

### ① 무엇을 논의하는가

엘캠퍼스의 업무 플랫폼에 AI 연동과 교육을 묶어 중소기업에 SaaS(인터넷으로 빌려 쓰는 소프트웨어)로 파는 사업이 **할 만한 사업인지** 검토한다. 다른 회사에 팔려면 사내용에는 없던 준비가 필요하다. 이 문서는 그 준비를 **서비스 구성요소별로 나눠** 무엇을 갖춰야 하고 얼마가 드는지 따진다. 그 비용을 바탕으로 **상품(패키지)과 가격**을 구성하고, **손익**을 예상한 뒤, **판단 기준**을 정하고 시장·기술/운영·재무·법/규제·조직 영역별로 판정한다.

사업 구상의 내용을 바꾸지 않고, 그 구상에 담긴 초기 추정(개발 기간, 투자, 손익분기 등)을 검증한다. 출처가 있는 숫자는 부록 A에 출처를 모았고, 검토자가 어림한 숫자에는 **(추정)**을 붙였다. AWS·도구 비용은 공시 단가에 쓰는 양을 어림해 곱했으므로 추정에 들어간다. 금액은 원화로 적었다(1달러 = 1,400원). 달러 단가는 부록 B에 모았다.

### ② 사업 구상

구상 단계에서 정한 내용이다. 투자 항목의 숫자와 착수 조건은 초기 추정이며, 3장 이후에서 검증한다.

| 구성 | 내용 |
|---|---|
| 대상 고객 | 자체 IT·보안 인력이 없는 30~100인 중소기업 |
| 상품 | ① 엘캠퍼스 사내 업무 플랫폼의 일정·프로젝트 관리 기능을 떼어, 고객사 이름으로 쓰게 하는 **화이트 라벨**(남의 제품에 자기 상표를 붙여 쓰는 방식) ② 고객마다 서버·DB를 따로 두는 **독립 보안 클라우드**(Silo 방식) ③ 고객이 자기 AI 키를 등록해 쓰는 **BYOK**(Bring Your Own Key) AI 연동. AI 사용료는 고객이 AI 회사에 직접 낸다 ④ 직무·법정의무교육과 생성형 AI 실무 교육 |
| 운영 | 서버·네트워크·백업은 AWS 운영 대행사 **MSP**(Managed Service Provider)에 맡기고, 개발팀은 앱을 맡는다 |
| 가격 | 월 구독 Lite 45만 원(30인 이하), **Pro 75~90만 원(50인 이하, 주력)**, Enterprise 250만 원 이상(100인 이상). 초기 도입비는 표준 온보딩 100만 원(연간 계약 시 면제), 맞춤 구축 500~1,000만 원 |
| 투자(초기 추정) | 개발 5~6개월, 초기 투자 5,000~6,000만 원, 월 운영비 1,500~2,000만 원 |
| 영업 | 기존 교육 고객 약 3,800곳의 교육 갱신 시점에 "교육비는 그대로, AI 교육 무상, 도입비 면제"로 제안 |
| 착수 조건 1~3 | MSP와 인프라 방식 합의, 개발자 3명(다른 업무와 겸직)의 시간 절반 이상 보장, 핵심 모듈만 5~6개월 안에 끝내는 범위 확정 |

## 2. 구성요소(서비스) 정의

서비스는 고객에게 보이는 네 가지와, 이를 여러 고객에게 제공하려고 뒤에서 필요한 두 가지로 이루어진다.

| 구성요소 | 무엇인가 | 고객이 얻는 것 | 고객에게 보이나 |
|---|---|---|---|
| **A. 업무 플랫폼** | 사내 업무 플랫폼의 일정·프로젝트 관리 기능을 바탕으로 한 업무 도구. 고객사 로고·도메인으로 쓴다(화이트 라벨) | 자기 회사 이름의 업무 도구 | 보임 |
| **B. 독립 보안 클라우드** | 고객마다 따로 두는 서버·DB·백업. AWS 서울 리전, MSP가 운영 | 다른 회사와 섞이지 않는 데이터 보관 | 보임 |
| **C. AI 연동** | 업무 플랫폼 안에서 AI 기능을 쓰게 하는 연결. 구상은 BYOK | 업무 도구 안에서 바로 쓰는 AI | 보임 |
| **D. 교육** | 엘캠퍼스의 직무·법정의무교육과 생성형 AI 실무 교육. 플랫폼 사용자가 LMS(학습 관리 시스템)로 연다 | 직원 AI 활용 교육 | 보임 |
| **E. 고객 관리·운영 체계** | 여러 고객의 환경을 한 곳에서 관리하는 운영 콘솔, 일괄 업데이트, 모니터링, 청구, 운영자 PC 관리 | 안정적인 서비스(간접) | 안 보임 |
| **F. 온보딩·고객 지원** | 도입 시 설정·데이터 이전·교육, 이후 문의 대응과 정기 지원 | 빠른 도입, 문제 해결 | 보임 |

여기에 개발·운영 전체에 걸리는 **공통 항목**(화면 디자인, 테스트, 법률 검토, 보안 점검, 보험 등)이 더해진다.

### 업무 플랫폼은 어디까지 만드나: 팔 수 있는 최소 수준

구상은 Lite를 "기본 프로젝트 관리 툴"로 정한다. "기본"을 어디까지로 보느냐에 따라 개발량이 크게 달라진다. 지금 사내 플랫폼에는 칸반·간트 같은 뷰와 권한 관리 화면이 없다(아래 비교). 반대로 먼데이·아사나의 상위 요금제 기능까지 만들면 그만큼 개발량이 늘어난다. 그래서 **같은 가격대의 해외 제품이 가장 싼 유료 요금제에서 주는 기능**을 최소 수준으로 잡았다.

**같은 가격대 제품이 주는 기능** (각 회사 공식 안내, 출처는 부록 A)
* **먼데이**: 가장 싼 Basic은 리스트·칸반 뷰만 준다. 한 단계 위 Standard부터 간트·캘린더 뷰, 자동화(월 250회), 게스트 3명, 대시보드가 들어간다. TASK 간 의존성과 세부 권한은 그 위 Pro부터다.
* **아사나**: 가장 싼 유료 요금제 Starter에 간트, 의존성, 커스텀 필드, 자동화, 리포트 대시보드, 게스트 무제한, 프로젝트별 권한(관리·편집·댓글)과 비공개 프로젝트가 들어 있다.
* Lite 45만 원을 30명이 쓰면 1명당 월 1.5만 원이다. 먼데이 Standard, 아사나 Starter와 비슷한 값이다(4장 ② 시장 가격 비교). 그래서 **리스트·칸반·캘린더·간트 네 가지 뷰와 게스트, 프로젝트 공개 범위**를 최소선으로 보았다.

**세 수준 비교**

| 기능 | 지금 사내 플랫폼 | 우리가 만들 최소 수준 | 먼데이·아사나에는 있지만 이번에 만들지 않는 것 |
|---|---|---|---|
| TASK 구조 | TASK·WBS[^wbs]·QA[^qa]·업무노트가 따로 논다. 하위 TASK, 의존성이 없다 | 모든 일을 TASK 하나로 통일. 하위 TASK, 단순 의존성 표시 | 앞 TASK가 밀리면 뒤 TASK 일정이 자동으로 밀리는 기능 |
| 뷰 | 게시판형 리스트, 웹 제작용으로 고정된 탭 | 리스트·칸반·캘린더·간트 | 워크로드, 포트폴리오 |
| 협업 | 댓글, 부서별 작업 패널 | 댓글, @멘션, 활동 로그, 파일 첨부·메일 알림 | 문서·화이트보드 내장 |
| 권한 | 권한 관리 화면이 없다 | 관리자·멤버·게스트 구분, 프로젝트 공개·비공개 | 필드 단위 세부 권한 |
| 현황 | 프로젝트 진행률 | 진행 현황 대시보드 | 커스텀 리포트 |
| 맞춤 | 없음 | 프로젝트 템플릿 몇 종, 엑셀 가져오기 | 자동화, 커스텀 필드·폼, 외부 앱 연동 |
| 기기 | PC 웹 | 웹, 모바일 화면 대응 | 모바일 전용 앱 |

[^wbs]: **WBS**(Work Breakdown Structure). 프로젝트의 일을 단계별로 쪼개 담당자와 일정을 붙인 작업 목록.

[^qa]: **QA**(Quality Assurance). 배포 전에 기능이 제대로 동작하는지 확인하는 품질 검증.

**최소 수준의 업무 기능을 만드는 데 걸리는 기간** (검토자 추정, 개발자 1명 기준). 계정·권한, 파일·알림, 내보내기, 모바일 화면은 3장 "A. 업무 플랫폼" 표에 따로 있어 여기서 뺐다.

| 기능 | 작업 기간 |
|---|---|
| 데이터 설계(TASK·프로젝트·하위 TASK·의존성) | 2주 |
| TASK 등록·수정, 하위 TASK, 담당자·마감일·상태·우선순위 | 2주 |
| 리스트 뷰(정렬·필터·검색) | 1주 |
| 칸반 뷰 | 1주 |
| 캘린더 뷰 | 1주 |
| 간트 뷰(단순 의존성 표시 포함) | 2주 |
| 댓글, @멘션, 활동 로그 | 1주 |
| 프로젝트 공개 범위, 게스트 | 1주 |
| 진행 현황 대시보드 | 1주 |
| 프로젝트 템플릿, 엑셀 가져오기 | 1주 |
| **합계** | **13주(약 3개월)** |

**이 범위로 가면.**
* 같은 값의 아사나 Starter보다 기능이 적다. 자동화와 커스텀 필드가 없다. 기능만으로는 이기기 어렵고, 독립 보안 클라우드·화이트 라벨·교육 묶음이 값을 받는 이유가 되어야 한다. 이 점은 기존 고객에게 확인한다(6장 ⑥).
* 출시 뒤 요청이 많을 것으로 보이는 커스텀 필드나 간단한 자동화 1~2개는 출시 후 보강(3장 표의 "기준" 칸, 2주)으로 두었다.

**지금 사내 플랫폼에서 어떻게 출발하나: 두 가지 방법**

| | 가. 사내 플랫폼 모듈을 떼어 고치기(발췌·경량화) | 나. 새로 만들기 |
|---|---|---|
| 내용 | 사내 플랫폼의 일정·프로젝트 관리 모듈을 떼어 내 다른 회사용으로 고친다 | 위 최소 수준을 기준으로 데이터 구조부터 새로 만든다. 사내 플랫폼은 화면 흐름의 참고로 쓴다 |
| 유리한 점 | 이미 쓰고 있는 화면과 업무 흐름(부서 간 요청 → 처리 → 결과물 → 검수)이 있다 | 권한·입력 검증·회사별 구조를 처음부터 넣을 수 있다 |
| 확인된 사실 | 사내 플랫폼은 퍼블리셔 출신 직원이 레드마인(게시판형 이슈 관리 도구) 대신 쓰려고 큰 계획 없이 만든 게시판형 사내 도구다(기획 책임자 확인). 2026-10-23 화면 점검에서 권한 관리 화면이 없고, 잘못된 입력값을 그대로 받으며, 작업 기록에 테스트 계정 정보가 그대로 적혀 있는 것을 확인했다 | 같음 |
| 업무 기능 작업 기간 | 재사용할 수 있는 만큼 약 3개월보다 줄어든다. 재사용 범위는 코드 진단 전에는 알 수 없어 0~3개월(0~2,180만 원)로 둔다 | 약 3개월(위 표) |
| 출시 전 투자 | 약 1억 4,100만~1억 6,200만 원(재사용 100%~0%) | 약 1억 6,200만 원 |
| 출시까지 | 1.5명분 약 10~12개월, 2명분 약 7.5~9개월 | 1.5명분 약 12개월, 2명분 약 9개월 |
| 어느 쪽이든 남는 일 | 칸반·캘린더·간트 같은 없는 뷰, 권한·입력 검증 같은 기반 결함은 고쳐야 한다 | 같음 |

이 문서의 기본 계산은 **나(새로 만들기, 약 3개월)**로 잡았다. 가로 갈 때의 손익은 5장 ⑤에 따로 넣었다. 재사용 100%는 가장 유리한 경우이고, 기반 결함과 없는 뷰는 어느 쪽이든 만들어야 한다. 재사용할 수 있는 범위는 개발팀의 코드 진단으로 확인한다(6장 ⑥).

## 3. 구성요소별 필요 요건과 비용

### 읽는 법

* **최소 요건**은 첫 고객에게 팔 수 있는 수준이고, **기준 요건**은 30~100곳을 사람 손을 덜 들이고 돌리는 수준이다.
* **작업 기간**은 개발자 **1명이 그 일만 할 때** 걸리는 기간이다. 실제로는 여러 명이 나눠 하므로 전체 일정은 3장 끝 "개발 일정"에서 따로 계산했다. 작업 기간은 모두 검토자 추정이다.
* **금액**은 작업 기간에 시장 인건비를 곱한 값이다. 시장 인건비는 한국소프트웨어산업협회 2025년 SW기술자 평균임금(개발자 월 694만 원, 디자이너 월 518만 원, 설계 전문가 월 1,015만 원; 급여·상여·퇴직금 적립·4대보험 포함)에 2026년 인상률 4.7%를 곱해, 개발자 **월 727만 원**, 디자이너 **월 542만 원**, 설계 전문가 **월 1,062만 원**으로 잡았다. 4.7%는 2차 출처라 협회 원문으로 확인해야 한다.

### A. 업무 플랫폼

### E. 고객 관리·운영 체계

**① 왜 필요한가.** 고객마다 서버와 DB를 따로 두면 **고객 수만큼 관리할 대상이 늘어난다.** AWS 백서는 이 방식의 대가로 운영이 복잡해지고, 업데이트가 느려지고, 고객 개설을 자동화해야 한다는 점을 든다. 그래서 모든 고객 환경을 **한 곳에서 다루는 관리 시스템**이 필요하다. AWS는 이를 "컨트롤 플레인"이라 부르고 예시 코드도 공개한다.

### F. 온보딩·고객 지원

**① 표준 온보딩.** 구상한 표준 온보딩에는 **화이트 라벨 설정, 기본 서버 개설, AI 키 연동** 세 가지가 들어 있다. 고객이 첫날부터 실제로 쓰려면 그 앞뒤 단계가 필요하다. 시간은 담당자 기준 (추정)이고, 비용은 지원 담당자 월 500만 원 기준 **하루 약 24만 원**으로 계산했다.

| 단계 | 하는 일 | 구상한 온보딩에 포함 | 걸리는 시간 |
|---|---|---|---|
| 1. 착수·정보 수집 | 조직도, 사용자 명단, 로고·색, 쓸 도메인, 관리자 지정 | 포함 안 됨 | 반나절~하루 |
| 2. 고객 환경 개설 | 고객 전용 서버·DB 생성(자동), 백업·모니터링 설정 확인 | **기본 서버 개설** | 1~2시간 |
| 3. 화이트 라벨 설정 | 로고·색, 고객 도메인 연결, SSL 인증서, 메일 발신 이름 | **화이트 라벨** | 1~2시간 |
| 4. 계정·조직 등록 | 명단 일괄 등록, 부서·권한 설정, 2단계 인증 안내 | 포함 안 됨 | 1시간~반나절 |
| 5. AI 키 연동 | 키 발급 안내, 키 등록·호출 테스트, 사용량 표시 확인 | **AI 키 연동** | 2시간~반나절 |

### ② 가격 근거

**원가로 본 하한: 이 아래로 팔면 고객 한 곳에서 남는 돈이 적다**

| 남기려는 비율(목표 공헌이익률[^목표]) | 변동비[^변동] 19만 원 | 29만 원 | 41만 원 |
|---|---|---|---|
| 50% | 38만 원 | 58만 원 | 82만 원 |
| 60% | 48만 원 | 72만 원 | 102만 원 |
| 70% | 63만 원 | 97만 원 | 137만 원 |

[^목표]: **목표 공헌이익률.** 고객 한 곳에서 받는 월 구독료 중, 변동비를 빼고 **남기려는 몫의 비율**이다. 남은 몫(공헌이익)은 고객 수와 상관없이 매달 나가는 고정비(개발 유지보수 인건비, MSP 월정액, 마케팅 등)를 갚고 이익을 내는 데 쓰인다. 계산은 **가격 = 변동비 ÷ (1 − 목표 비율)**이다. 예를 들어 변동비가 29만 원인 고객에게서 60%를 남기려면 29 ÷ 0.4 = 약 72만 원을 받아야 한다. 이 경우 72만 원 중 29만 원은 그 고객 비용으로 나가고, 43만 원(60%)이 고정비 회수에 쓰인다. 표의 50·60·70%는 회사가 정한 목표가 아니라 세 경우를 나란히 보여 주는 비교값이다. 구상 단계에서 가정한 값은 70%다.

[^변동]: **변동비.** 고객이 **한 곳 늘 때마다 매달 함께 늘어나는 비용**이다. 고객이 없으면 0이고, 고객이 10곳이면 10배가 된다. 이 문서에서는 3장 비용 집계 ④의 네 가지를 더한 값이다. ① 그 고객 전용 서버·DB, ② 보안·통제(위협 탐지·설정 기록·방화벽·암호화 키), ③ MSP의 고객별 관리비, ④ 고객 지원 인건비(지원 담당자 1명이 30~60곳을 맡는다고 보고 나눈 값)다. 19만·29만·41만 원은 각 항목을 낮게, 중간으로, 높게 잡아 더한 것이다. 반대로 **고정비**는 고객 수와 상관없이 매달 나가는 비용이다. 신규 고객 온보딩비(1곳당 한 번)와 AI 사용료(BYOK라 고객이 직접 냄)는 변동비에 넣지 않았다.

**고정비를 갚으려면: 목표 고객 수에서 손익이 0이 되는 평균 월 구독료** (고정비 월 1,900만 원 + 온보딩 월 약 230만 원)

### ③ 요금제별 가격 판단

* **Pro 75~90만 원.** 원가로는 설명이 된다. 변동비가 중간(29만 원)이면 고객 1곳에서 61~68%가 남고, 40곳에서 손익이 0이 되는 평균 구독료는 약 82만 원이다. 50인 고객이면 1명당 1.5~1.8만 원으로 경쟁 제품과 비슷하다. 30인 고객이면 1명당 2.5~3.0만 원으로 더 비싸다. 고객이 이 가격을 내는지는 LOI(구매 의향서)로 확인해야 한다(6장 시장 판정).
* **Lite 45만 원.** 변동비가 19만 원이면 58%, 29만 원이면 36%가 남는다. 이 가격을 유지하려면 Lite 고객의 원가가 낮아야 한다. 예를 들어 네트워크를 함께 쓰고, 지원을 정기 지원 대신 요청할 때만 하는 식이다. 이런 원가가 확인되는지가 Lite 가격의 근거가 된다.
* **Enterprise 250만 원 이상.** 전용 네트워크(서버비 월 약 15만 원)와 늘어나는 지원 비용을 넣어도 원가 하한보다 충분히 높다.
* **표준 온보딩 100만 원(연간 계약 시 면제).** 면제하면 매달 3~4곳 기준으로 월 약 200~260만 원을 우리가 부담한다. 5장 손익에 이미 들어 있다.

구상한 영업 경로는 기존 교육 고객의 교육 갱신 시점이다. 이 경로만으로 매달 3~4곳이 나오려면 어느 정도의 전환율이 필요한지 거꾸로 계산했다.

사내 개발자 인건비는 이미 나가고 있는 돈이다. 이를 빼고 **새로 나가는 돈**만 보면 출시 후 **5~10개월**(고객 17~30곳)에 월 현금 흐름이 플러스가 된다. 새로 나가는 돈은 출시 전 외부 비용, AI 교육 콘텐츠 제작비(외주로 볼 때), 외부 고정비, 장애 대응비, 고객 지원 인건비, 온보딩비다. 그때까지 들어가는 현금은 **약 5,200만~7,300만 원**이다(변동비 19~41만 원, 매달 신규 3~4곳). 지원 담당자는 새로 뽑는다고 보았다.

### ⑦ 정리

* **매달 3곳**이면 착수 후 50~53개월(4년 2~5개월)이다. **매달 2곳**이거나, 평균 구독료가 65만 원인데 매달 3곳이면 출시 후 5년 안에 회수하지 못한다.

* 결과를 가장 크게 흔드는 것은 ① 평균 구독료(Lite 비중), ② 매달 신규 고객 수, ③ 고객당 변동비(지원·MSP 원가) 순이다.
* 이 가운데 매달 신규 고객 수는 근거가 없는 가정이다(②).

## 6. 판단 기준과 판정

### ① 판단 방법

**판정 척도.** 모든 영역과 종합 판정에 같은 네 단계를 쓴다.

| 판정 | 뜻 |
|---|---|
| **가능** | 확인된 근거만으로 할 수 있다 |
| **조건부** | 정해 둔 조건이 확인되면 할 수 있다. 조건과 확인 방법을 함께 적는다 |
| **보류** | 판단에 필요한 근거가 없어 지금은 가능·부적합을 가를 수 없다 |
| **부적합** | 근거상 할 수 없거나, 해도 투자를 회수하지 못한다 |

**영역 판정을 종합 판정으로 묶는 규칙.** 영역 판정을 종합 판정으로 묶는 규칙은 다음과 같다.
1. 한 영역이라도 **부적합**이면 종합도 부적합이다.
2. 부적합은 없고 **보류**가 하나라도 있으면 종합은 보류다. 그 영역의 근거가 확인되면 다시 판정한다.
3. 모든 영역이 **가능**이면 종합도 가능이다.
4. 가능과 조건부만 있으면 종합은 **조건부**이고, 각 영역의 조건을 모두 모은 것이 종합의 조건이다.

**재무의 투자 기준.** 허용할 투자 회수 기간은 경영진이 정할 사항이다. 이 문서는 기준을 정하지 않고, 회수 기간을 출시 후와 착수 후 두 기준으로 모두 보여 준다. 허용 기간에 따라 결과가 어떻게 갈리는지는 ⑤ 재무에 정리했다. 출처가 있는 일반 관례는 찾지 못했다.

**결과를 가르는 네 값.** 5장 결과를 가르는 값과 그 확인 방법, 넘어야 할 선이다. 기준선은 5장 계산에서 나온 것이며, 다시 계산하면 함께 바뀐다.

| 판단 값 | 확인 방법 | 넘어야 할 선(현재 계산) | 못 넘으면 |
|---|---|---|---|
| 평균 월 구독료(요금제 비중) | 기존 교육 고객 LOI(구매 의향서). 월 75만 원 이상 조건으로 10곳 이상, 또는 유료 선계약 5곳 이상 | 평균 80만 원 이상 | 65만 원이면 매달 3곳으로는 출시 후 5년 안에 회수하지 못한다 |
| 매달 신규 고객 수 | LOI 응답률, 30~100인 고객 수, 교육 갱신 일정 | 매달 3곳이면 착수 후 50~53개월, 4곳이면 40~43개월에 회수 | 2곳이면 출시 후 5년 안에 회수하지 못한다 |
| 고객당 변동비 | MSP 2~3곳 견적, 지원 범위 확정 | 월 29만 원 이하 | 41만 원이면 매달 4곳이어도 출시 후 42개월(착수 후 51~54개월)에 회수한다 |

### ④ 종합 판정

**종합: 보류.** ①의 규칙 2에 따른다. 부적합 영역은 없고, 시장이 보류다. 시장을 뺀 네 영역에서는 사업을 할 수 없게 만드는 요소를 찾지 못했다. 그러나 성패를 가르는 **"30~100인 기업이 월 75~90만 원을 내고 쓰던 업무 도구를 바꾼다"에 근거가 없고, 손익을 가르는 매달 신규 고객 수에도 근거가 없다.** 이 둘이 확인되기 전에는 타당한지 부적합한지를 가를 수 없다. 착수 조건 1~3도 충족되지 않았다. 시장 확인에는 개발이 필요 없고, 기존 고객 접점으로 2~3개월 안에 할 수 있다.

**판정을 바꿀 근거**
* **조건부로:** 기존 고객 중 월 75만 원 이상 조건의 LOI 10곳 이상, 또는 유료 선계약 5곳 이상. 인터뷰에서 "지금 업무 도구를 바꾸겠다"는 응답이 절반 이상. LOI 응답률로 본 신규 고객이 매달 3곳 이상. 여기에 착수 조건 1~3이 충족되면 착수할 수 있다.
* **부적합으로:** 인터뷰 대부분이 "AI 교육은 좋지만 업무 도구는 지금 것을 쓰겠다"고 답하거나, 받을 수 있는 평균 가격이 월 65만 원 아래로 나오거나, 신규가 매달 2곳 수준일 때. 이 경우 출시 후 5년 안에 투자를 회수하지 못한다(5장 ⑤).

필요는 근거가 있다. 그러나 이 가격에 사고 업무 도구를 바꾸는지에 대해서는 찬성 근거가 없고, 반대 근거(예산 애로, 큰 새 지출, 무료에 가까운 AI 교육 대안, 협업 도구 경쟁)는 있다. 필요와 지불·전환을 나눠 보면, 필요는 찬성 쪽으로, 지불·전환은 반대 쪽으로 기운다. 그러나 지불 의향을 직접 확인한 자료(LOI, 구매 사례)가 없어 판단을 확정할 수 없으므로 **보류**다.

#### 기술·운영: 조건부

* **업무 플랫폼의 출발점은 두 가지다(2장).** 사내 플랫폼의 모듈을 떼어 고치는 방법과, 같은 가격대 제품 수준으로 새로 만드는 방법이다. 이 문서는 새로 만드는 경우(업무 기능 약 3개월)로 계산했다. 재사용 범위는 개발팀의 코드 진단으로 확인해야 한다.
* **고객마다 따로 설치하는 방식(Silo)은 기술적으로 타당하다.** 회사별 데이터 분리를 새로 짤 필요가 없고, 규제·보안 요구가 강한 고객에게 맞으며, 한 고객의 장애가 다른 고객에게 번지지 않는다. 대가는 고객 수만큼 늘어나는 관리 대상이다. AWS 백서는 고객별 계정 20개는 관리할 만하지만 1,000개면 효율이 떨어진다고 본다. 그래서 고객 관리·운영 체계(3장 E)가 출시 전에 있어야 한다.
* **출시까지 9~12개월이 걸린다(초기 추정 5~6개월).** 최소 요건은 개발자 1명 기준 약 18개월 분량이다. 1.5명분이면 약 12개월, 2명분이면 약 9개월이다. AI 코딩 도구를 쓰면 1.5명분 기준 약 9개월이다(3장 비용 집계 ①).
* **MSP가 대신하지 않는 일이 있다.** 전 고객 일괄 업데이트, 고객별 DB 구조 변경, 앱 장애 대응, 운영 콘솔은 개발팀 몫이다.

조건은 ① 사내 코드 재사용 범위 진단 ② 최소 범위 고수 ③ 일괄 업데이트·DB 변경 자동화 ④ MSP 견적과 책임 범위 확정 ⑤ 개발 시간 보장이다.

## 부록 C. AI를 상품에 포함해 파는 방식 (참고)

구상은 BYOK로 정했다. 아래는 AI를 우리 상품에 포함해 파는 방식을 검토한 참고 자료이며, **판정과 손익에는 쓰지 않았다.**

### ① 검증 과제: AWS 서울 리전 AI(Bedrock)를 우리가 팔 수 있는가

Bedrock은 AWS가 여러 AI 모델(Claude 등)을 사용량만큼 요금을 받고 제공하는 서비스다. 이를 우리가 고객에게 넘겨 팔 수 있는지는 **아직 결론을 낼 수 없고, 검증이 필요한 과제**다. 지금까지 확인한 것과 모르는 것, 검증 방법을 나눠 적는다.

*지금까지 확인된 것*

| 항목 | 내용 | 출처 |
|---|---|---|
| 서울 리전에서 Claude 사용 가능 | 2026-09-29부터 Claude Opus 5·Sonnet 5를 서울 리전에서 쓸 수 있다. 요청과 데이터가 서울 리전 안에서 처리된다 | AWS 블로그 2026-09-29 |
| AWS가 재판매를 허용 | 2025-10-14부터 Bedrock을 AWS 공인 리셀러 파트너가 재판매할 수 있다. Claude는 "**일정한 제한 아래**"만 가능하고, 제한 내용은 공개되지 않았다 | AWS 파트너 블로그 2025-10-14 |
| 리셀러 파트너 자격 | 리셀러 프로그램 중 하나(Distribution)는 파트너 등급 Select 이상이 대상이다. Select는 연회비 약 350만 원, AWS 교육 이수자 4명, 자격증 보유자 4명, 고객 실적 3건이 필요하다. 다른 프로그램(Solution Provider)의 요건은 확인하지 못했다 | AWS 파트너 등급 안내 |
| Claude 이용 약관 | 고객은 Claude를 "**자기 고객에게 제공하는 제품·서비스를 구동**"하는 데 쓸 수 있다. 그러나 "**Anthropic이 승인하지 않으면 재판매할 수 없다**". 무엇이 "구동"이고 무엇이 "재판매"인지는 정의돼 있지 않다 | Anthropic on Bedrock 약관(2025-08-18판) |

*아직 모르는 것*

1. 우리 플랫폼 기능 안에 AI를 넣고 그 비용을 구독료나 사용료로 받는 것이 약관상 "구동"인지 "재판매"인지
2. Claude 재판매의 "일정한 제한"이 무엇인지
3. MSP를 거쳐 AWS 요금을 낼 때 Bedrock(특히 Claude)도 함께 청구되는지, 할인이 있는지
4. 서울 리전 Claude의 처리 한도(동시에 몇 명까지 쓸 수 있는지)와 늘리는 절차

*검증할 방식과 검증 방법*

| 방식 | 내용 | 검증할 것 | 누구에게 |
|---|---|---|---|
| **포함형** | 우리 AWS 계정으로 AI를 호출해 플랫폼 기능으로 제공하고, 비용은 구독료에 넣거나 사용량만큼 받는다 | 위 1·4번 | 법무, AWS 담당자 |
| **정식 재판매** | 고객의 AI 사용 자체를 우리가 AWS 대신 판매·청구한다 | 위 2번, 파트너 자격을 갖출 수 있는지 | AWS 파트너 담당자 |
| **MSP 경유 청구** | MSP가 우리 AWS 요금(Bedrock 포함)을 대신 청구한다 | 위 3번 | MSP 2~3곳 |

*검증 결과에 따른 갈래*

* 포함형이 "구동"으로 확인되면: BYOK와 함께 선택지로 둘 수 있다. 이때는 개발 약 2주(약 360만 원)가 더 들고, AI 원가를 우리가 지므로 사용 한도가 있는 가격 구조가 필요하다(아래 ②).
* "재판매"로 판단되면: Anthropic 승인이나 파트너 자격이 필요하다. 업무 플랫폼 사업에 비해 부담이 크므로 BYOK만 유지한다.
* 어느 쪽이든 BYOK는 그대로 가능하다. 다만 고객이 OpenAI·Anthropic에서 직접 키를 받아 쓰면 "데이터가 서울 리전 안에서 처리된다"고 말할 수 없다. 이 설명은 포함형이거나, 고객이 서울 리전 Bedrock 키를 쓸 때만 할 수 있다.

### ② 포함형으로 판다면 가격 구조

50인 기준 AI 원가는 월 14~65만 원(Claude Sonnet 단가로 낸 추정)으로 차이가 크다. 원가에 20%를 얹으면 월 17~78만 원, 1명당 0.3~1.6만 원이다. **정액으로 받으면 많이 쓰는 고객에서 손해가 난다.** 그래서 "1명당 사용 한도 + 넘는 만큼 별도"가 원가 구조와 맞는다 (추정). 넘는 만큼 받을 때는 '모델 사용료'가 아니라 '플랫폼 AI 기능 사용료'로 정하고, 법무 검토를 받아야 한다. 참고로 ChatGPT Business는 1명당 월 2.8만 원이다.
