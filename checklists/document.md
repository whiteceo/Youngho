# 검토 문서 점검 체크리스트

이 체크리스트는 신사업 타당성 검토 문서를 보고하기 전에 문서 담당 팀장이 스스로 확인하는 항목이다. 7개 원칙(경영진 지시, 2026-10-25) 아래에 문서 업무에 맞는 하위 항목을 둔다. 보고 끝에는 원칙별 결과를 한 줄씩 붙인다.

## 1. 목적: 경영진이 무엇을 결정해야 하는지 분명한가

- [ ] 1.1 요약(1장) 첫 화면에 종합 판정과 그 이유가 한 문단 안에 있다.
- [ ] 1.2 경영진이 이번 회의에서 결정할 사항(예: 시장 검증 착수 여부, 예산, 투자 한도·허용 회수 기간 기준)이 요약과 마지막 장 모두에 적혀 있다.
- [ ] 1.3 다음 단계가 무엇이고 비용·기간이 얼마인지 적혀 있다.
- [ ] 1.4 거시 메시지(기업 가치, 신사업 판단 방법론)가 판정을 대신하지 않고 판정 뒤에 온다.

## 2. 전제: 결론이 서려면 참이어야 할 전제를 의심했는가

- [ ] 2.1 판정별로 "이것이 틀리면 판정이 바뀌는 전제"를 꺼냈다(이슈 트리: 시장, 기술·운영, 재무, 법·규제, 조직).
- [ ] 2.2 핵심 전제(가격·ARPU, 매달 신규 고객 수, 이탈률, 인건비, 개발 기간, CAC)마다 근거와 민감도가 있다.
- [ ] 2.3 판정이 바뀌는 조건(예: 재무가 부적합이 되는 경우)이 명시되어 있다.
- [ ] 2.4 빠진 축이 없는지 확인했다(경쟁, 법인 구조, 조직 역량, 기존 사업에 대한 영향).

## 3. 근거 수준: 사실·판단·추정을 구분했는가

- [ ] 3.1 사실에는 출처가 있고 부록 A에 실려 있다.
- [ ] 3.2 추정과 판단은 "추정", "본다", "판단했다" 같은 표현으로 드러난다.
- [ ] 3.3 표현 세기가 근거 세기를 넘지 않는다(가설 위에 단정적 권고를 쌓지 않음, 법령 해설 사이트로 확인한 것은 "원문 미확인" 표시).
- [ ] 3.4 확인하지 않은 사항은 6.6 확인 필요 항목에 있고, 확인된 사항은 본문에서 사실로 바뀌었다.

## 4. 정합성: 한 목소리인가

- [ ] 4.1 핵심 숫자(CAPEX, 월 고정비, 회수 기간, 흑자 전환, 최대 누적 적자, 필요 ARPU, 시장 규모)가 1장·4\~6장·7장에서 같다.
- [ ] 4.2 용어가 같다(Stage/Phase, 사내 인력 포함/현금 기준, 착수 후/출시 후, PM).
- [ ] 4.3 영역별 판정이 1장, 6장 판정표, 6.5 본문에서 같다.
- [ ] 4.4 덱과 문서의 숫자·표현이 같다(덱 담당 팀에 바뀐 표현을 직접 알렸다).
- [ ] 4.5 장·절 상호 참조(예: "6.5", "7.3")가 실제 위치를 가리킨다.

## 5. 청중: 처음 읽는 중간 관리자가 이해하는가

- [ ] 5.1 업무 용어는 처음 나올 때 풀이가 있다.
- [ ] 5.2 특정인을 비판하는 것으로 읽히는 문장이 없다(관행 → 방법론 구도, 진단의 주체 명시).
- [ ] 5.3 장밋빛으로 읽히는 문장이 없다(장점과 같은 무게로 약점·위험 서술).
- [ ] 5.4 주어가 분명하고, 기간은 년+개월로 쓴다.

## 6. 실물 검증: 직접 다시 계산하고 원문과 대조했는가

- [ ] 6.1 손익 모델(model_v6.py)을 다시 돌려 문서의 핵심 숫자와 대조했다.
- [ ] 6.2 시장 규모, 기업 가치 계산을 원자료 파일(research/)과 대조했다.
- [ ] 6.3 인용한 외부 수치는 원문(또는 원문을 인용한 1차 자료)과 대조했다. 대조하지 못한 것은 그렇다고 적었다.

## 7. 독립 검증: 다른 눈으로 확인했는가

- [ ] 7.1 작성자가 아닌 별도 검수 에이전트가 이 체크리스트로 문서를 읽고 지적 사항을 냈다.
- [ ] 7.2 지적 사항마다 반영 또는 반영하지 않은 이유를 남겼다.
